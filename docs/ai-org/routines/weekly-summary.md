# 週次経営サマリ＋AI組織自己点検

実行: 毎週金曜 17:00 JST ／ 出力先: Notion「AI組織 運行ボード」＋Gmail下書き

## 手順

1. **読み込み**: 今週の運行ログ・案件DB・タスクDB・パイプライン・継続率の物差し・
   来週のGoogleカレンダーMTG予定。
2. **週報作成**: 事業責任者が5分で全体を把握できる形で:
   - 納品・進捗ハイライト
   - リスク（締切・健康度🔴🟡）
   - 売上パイプラインの変化（商機と金額）
   - 継続率の物差しの推移
   - 来週の意思決定事項（MTG・承認待ちドラフト）を箇条書き最大5個
3. **機会損失レポート**: 遅延中の案件ごとに「遅延日数×原因分類（当社実装／先方ボール／
   仕様変更／その他）」と「凍結中の金額（想定月額＋納品完了トリガー待ちの追加提案額）」を
   集計し、先週比の増減を表示する。着手ゲート3点（受入基準・工数見積・バッファ付き納期）の
   充足率も表示する。週報の冒頭3行に機会損失の合計額を含める。
4. **出番監査**: 来週の全クライアントMTGを仕分けする:
   - **委任可能**（オンライン進捗定例・型どおりのアップセル商談）→ 担当スタッフ案＋準備パックの有無を明記
   - **事業責任者必須**（リアルMTG・新規商談クロージング・期待値調整/クレーム・温度感低下時）
   事業責任者のMTG拘束時間（今週実績/来週予定）と委任度を計測し、推移を運行ボードに記録する。
   委任提案には必ず根拠を添える。割当の確定は人間が行う。
5. **ウォッチドッグ（自己点検）**: 今週、日次PM巡回と週次CS/グロース便が
   予定通り運行ボードにログを残しているか確認する。
   抜けがあれば原因を調べ、週報の冒頭に「⚠️AI組織の運行異常」として報告する。
   台帳と現実の乖離が疑われる案件も指摘する。
   （過去にPM自動化が約2週間停止しても誰も気づかなかった教訓による）
6. **記録**: 運行ボードの運行ログに「YYYY-MM-DD（金）週次経営サマリ」見出しで追記。
7. **送付準備**: 同内容を事業責任者宛のGmail下書きにする
   （件名「【AI組織週報】MM/DD週 AI業務効率化支援」、冒頭3行で結論＝機会損失合計額を含む。
   出番監査の結果＝来週出席が必要なMTGだけを明示する）。
8. **クライアント向け週次報告**: 今週分が未生成の案件があれば、
   クライアント向け進捗報告のコピペ可能文面を生成して運行ボードに記載する。

## ガードレール

- クライアントへの送信はしない
- 金額・契約の決定はしない
